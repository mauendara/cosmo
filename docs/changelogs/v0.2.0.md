# v0.2.0

Pre-release. Not production ready.

## Added

- New harness adapters:
  - `ori-claude` — Claude Code CLI routed through [Ori](https://github.com/badlogic/ori) to OpenRouter, with real, confirmed-working `PreToolUse` gating.
  - `claude-openrouter` — the native `claude` binary talking to OpenRouter directly (no `ori` process in the loop), which avoids a real `thinking.display` 400 error that non-Anthropic models hit through `ori`.
  - `codex` — OpenAI Codex CLI as a first-class harness: structured JSONL output, explicit audited hooks, isolated personal configuration, saved-login authentication, and process-tree cancellation.
- `cosmo_branch` base-branch isolation mode (`cosmo init --base-branch-mode cosmo_branch`): forks an isolated branch off the real base branch so template/harness scaffolding never lands on the developer's actual `develop`/`main`.
- `cosmo init -i` / `--interactive`: a wizard mode that prompts for target path, harness, project template, base-branch mode, and optional per-harness model overrides.
- Per-role model configuration — `harness.propose_model` / `implement_model` / `review_model` — so planning, implementation, and review can each run on a different model.
- Console-facing timestamps now render in the host's local timezone (storage is still UTC).
- `resume_at_stage` gained a `VALIDATING` stage; `cosmo queue retry` gained `--resume-at-validating`, `--resume-at-committing`, and `--keep-implementation` flags for resuming a blocked task without redoing already-successful work.
- Adaptive `IMPLEMENTING` turn/wall-clock budgets that grow automatically for a task that's shown real, well-understood progress, instead of a fixed ceiling regardless of task shape.
- Diff-only review by default, with a longer review budget granted only to tasks whose spec calls for live/visual verification.
- Orphaned dev-server/process reaping after every task attempt (propose/implement/review), not only on a forced cancellation.
- A structural allow-list (assertion count, skip annotations, line-delta) letting a session make a scoped, justified test-file edit without a blanket `allow_test_edits` grant set in advance.
- New events: `task.orphan_detected`, `task.review_repeat_rejection`.

## Fixed

- `REVIEWING` could silently discard an already-approved verdict when the review session changed its working directory first, writing `.cosmo/review-result.json` to the wrong path — forced a costly, unnecessary re-`IMPLEMENTING` retry.
- The `Task` (subagent-spawn) tool was not covered by the one-shot-hazard guardrails that already covered `Bash`/`ScheduleWakeup`/etc.
- A task that crashed mid-run (`PROPOSED`/`IMPLEMENTING`/`VALIDATING`/`REVIEWING`/`FAILED_RETRY`) had its worktree wiped and its work redone from scratch instead of resuming in place.
- The gitleaks secret scan could false-flag noise inside gitignored/untracked build artifacts (e.g. minified vendor JS) and block a fully correct task.
- A hard provider budget/key ceiling was retried like an ordinary transient error instead of failing fast with an actionable message.
- `cosmo init`'s git-identity step no longer offers the `Cosmo <cosmo@...>` identity as a default for commit authorship — a real name/email is always required, and the chosen identity now syncs into the target repo's own `[git]` config.

## Known limitations

Documented, not new to this release: no template-aware gate for stacks beyond Java+Spring/Vite+React, gate build commands are hardcoded rather than configurable, and a handful of real-invocation validations (system-wide systemd install, a real circuit-breaker-triggered `cosmo run resume`, a real 5-hour quota exhaustion window) remain outstanding. See `docs/v9-out-of-scope-desirables.md` and `docs/v8-validations-for-later.md` for the full, current list.
